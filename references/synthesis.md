# 全书综合:怎么写 book.json

输入是 `bg digest` 给出的全部章节笔记。这一步不再读原文(除非要核实某个细节),而是**在笔记之上思考**:这些章合起来到底论证了什么。

## 1. 核心问题、论点、摘要

- `question`:这本书试图回答的那个问题。一本书通常只有一个中心问题;找不到,就问"如果作者只能留一章,他在回应谁的什么困惑"。
- `thesis`:作者的回答,一句话(≤120 字)。必须是**有人可能不同意**的判断,而不是话题描述。
  - ✗ "本书探讨了组织学习与反馈的关系。"(话题)
  - ✓ "组织学不会,不是因为缺少反馈,而是因为反馈来得太迟以至于被归到错误的原因上;缩短或标记这段延迟比增加反馈量更有效。"
- `abstract`:一段话(≤400 字),按"问题 → 核心回答 → 主要理由 → 作者的做法/建议 → 作者承认的边界"的顺序。
- **不要照搬 brief.json。** 检视阅读时的假设常常只对了一半:对比各章的 core,看论点是否需要收窄、加条件或改重点。

## 2. 支柱(pillars)

支柱是"如果它倒了,核心论点就站不住"的 2–7 个关键论断。

- **自下而上归纳**:把各章 core 摆在一起,问"它们合起来在证明哪几件事"。一根支柱通常跨多章;一章也可能服务多根支柱。
- 支柱 ≠ 章节,也 ≠ 书的"部分"。如果你的支柱和目录一一对应,多半是在复述结构而不是提炼论证。
- `statement`:一句完整的判断。`how`:它如何支撑核心论点(去掉它,论点缺什么)。
- `claims`:它建立在哪些章节命题之上(必须是 core)。只列直接构成这根支柱的 2–6 条;它们各自的理由和证据会通过 links 自动归到支柱下面。
- `depends_on`:支柱之间的依赖(P3 要成立,先得接受 P1)。这是读者理解"论证顺序"的关键。
- 方法型的书:方法本身可以是一根支柱("按这五步做能解决问题"),它依赖前面解释"为什么"的支柱。

校验会提示:没有连到任何支柱的 core(要么挂进去,要么降级);大量章节没有进入任何支柱(支柱可能只概括了半本书)。纯背景章不进支柱是正常的——在阅读建议里标 skim/skip 并说明即可。

## 3. 跨章关系(links)

章内关系已在各章笔记里。这里补**跨章**的,每条写 `note`:

- 后面的方法步骤依赖前面的哪个概念/结论(`requires`);
- 分在两章讲完的因果回路(两条方向相反的 `causes`);
- 后文对前文的修订(`refines`)、限定(`limits`);
- 后面的证据支持前面的主张(`supports`)。

只连对理解论证有用的;十几条有分量的跨章关系胜过一百条琐碎的。

## 4. 概念表(concepts)

- 合并各章的概念:同一概念的不同叫法放进 `aka`;`refs` 汇总各章的出处。
- **含义有演变**的(作者后来修订了定义),`def` 写最终版本,`evolution` 写"第 X 章最初定义为……,第 Y 章修订为……,差别在于……"。这是读者最容易带着旧理解读下去的地方。
- **易混的概念对**,写 `vs`:`[{"term": "另一个概念", "diff": "区别在于……"}]`。
- 排序按首次出现。

## 5. 阅读建议(chapters)

对每一章给 `priority` 和 `why`:

- `must` 精读:论证的承重墙,或导读无法替代(关键论证的细节、需要亲自判断的证据)。
- `skim` 略读:论点简单、看导读已足够,但有个别段落值得看。
- `skip` 可跳过:背景回顾、重复、与主论证关系不大。

`why` 要具体到"为什么是这个级别、读的时候看什么"。全部标 must 等于没有建议。

## 6. 审视(critique)

这是导读里**唯一**表达你自己判断的地方,页面上会明确标注"不是作者观点"。每条必须有 `targets`(支柱 id、命题 id 或 `thesis`)。

| type | 写什么 |
|---|---|
| `gap` 论证缺口 | 结论比证据走得远的地方:只有轶事支撑的支柱、从相关跳到因果、样本无法代表结论所指的人群、关键一步没有论证 |
| `assumption` 隐含假设 | 论证要成立必须为真、但作者没有明说或没有辩护的前提 |
| `objection` 可能的反驳 | 一个讲理的反对者会怎么说。只写能从书的内容推出的反驳;不要编造书外的研究或数据 |
| `scope` 适用边界 | 结论在什么范围内有效(可综合作者自己的 caveat 和你的判断) |
| `strength` 扎实之处 | 证据特别硬、论证特别严密的地方——告诉读者哪些可以放心采信 |

做法:逐根支柱看它的证据构成(digest 里每条证据都标了类型)。问:这根支柱最硬的证据是什么?去掉轶事还剩什么?作者有没有考虑其他解释?然后看支柱之间的推理:从 P1+P2 到 P3,中间有没有跳步?

要求:至少包含 gap/assumption/objection 中的一种;具体到"哪条证据、哪一步推理",不写"论证不够充分"这种空话;不确定的事用不确定的语气。

## 7. 自测题(questions)

目的:让读者检验自己是否真的懂了,而不是"看过了"。每题带 `claims`(答案依据的命题/支柱 id)。

| level | 考什么 | 例 |
|---|---|---|
| `recall` 回忆 | 书里说了什么 | "作者认为 X 的根本原因是什么?" |
| `explain` 解释 | 为什么、如何相连 | "为什么作者说 A 必须先于 B?""第 6 章对'X'的定义和第 2 章差在哪?" |
| `apply` 应用 | 换一个书里没有的情境 | 给一个小场景:"按作者的框架,这里出了什么问题?该怎么做?" |
| `evaluate` 评判 | 论证的质量 | "哪根支柱证据最弱?""作者承认自己的方法在什么情况下失效?" |

- 8–20 题,四个层次都要有,explain + apply + evaluate 占多数。
- **必须读过这本书才能答对。** 靠常识能猜到的题没有价值。
- 专门为最容易读错的地方出题:作者反对的观点("X 是作者的主张吗?")、被修订的概念、易混概念、埋在中段的关键论断。
- 答案简明(2–4 句),给出要点;应用题的答案说明用到了书里的哪个论断。

## 8. 带走什么(takeaways)

2–5 条。方法型的书写"可以去做的事";论证型的书写"看问题的方式会有什么不同"。每条都应是这本书特有的,而不是放到任何书上都成立的鸡汤。

## 综合完成后

`bg check -w work`。错误必须修;提示逐条处理。然后进入独立核查。
