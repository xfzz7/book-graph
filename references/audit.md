# 独立核查

目的:在交付前,用一双没有先入之见的眼睛,对照原文检查笔记有没有走样。机器校验只能保证"锚点存在、没有抄录";**意思对不对**只能靠这一步。

> 如果你是被派来做核查的子代理:你只需要本文件、`<work>/audit/packet.md`、`<work>/audit/verdicts.json` 和 `<work>/source/`。不要去读 notes/ 或 book.json 的其他部分,也不要修改它们——你的任务是判定,不是修复。

## 做法

1. 打开 `audit/packet.md`。A 部分是全书层面(核心论点、各支柱),B 部分是逐条命题,每条下面附了它引用的原文段落。
2. **A. thesis**:完整阅读序言/导论和结语所在的 `source/cNN.txt`(`source/manifest.json` 里有章节表),判断 packet 里的核心论点是不是作者自己的中心主张——有没有说大了、说偏了、把次要观点当成中心、或者漏掉作者反复强调的关键条件。
3. **A. 各支柱**:支柱陈述是否忠实概括了它名下的命题?有没有加入这些命题里没有的内容?
4. **B. 逐条命题**:只依据所附的原文段落判断。若段落本身看不出上下文(例如无法判断是谁的观点),去 `source/` 读这一段前后各几段再判断。重点检查:
   - **立场**:原文里这是作者的主张,还是作者引述/批评的别人的观点?`kind=counter` 的条目反过来查:原文里作者真的不同意它吗?
   - **事实**:数字、人名、机构、年份、因果方向、比较的对象是否与原文一致?
   - **限定**:原文的条件("在……情况下""往往""样本中")有没有被丢掉,使结论变强了?
   - **出处**:所引段落是否真的在说这件事?
5. 把结论填进 `audit/verdicts.json` 中对应条目的 `verdict` 和 `note`(其他字段不要动):

| verdict | 含义 |
|---|---|
| `ok` | 忠实。措辞不同但意思、强度、立场都对 |
| `distorted` | 走样:夸大/弱化、丢了关键限定、数字或因果方向错、把两件事混成一件 |
| `unsupported` | 所引段落里找不到依据(可能是凭印象写的,或锚点指错了地方) |
| `misattributed` | 立场错:把对手的观点当成作者的,或把作者的观点标成对手的 |

`note`:非 ok 时必须写,一句话指出**哪里不对、原文实际怎么说**(转述,不要大段引用)。

## 判定尺度

- 转述允许换词、合并、省略次要细节。问题只在于:一个只读了这条笔记的读者,会不会对原书形成**错误**的理解。
- 拿不准时倾向于标出来并在 note 里说明疑点——漏报的代价比误报高。
- 不要因为"我觉得作者说得不对"而判不通过;核查的是笔记是否忠实于原书,不是原书是否正确。

## 核查之后(由写笔记的一方完成)

- 对每个非 ok 的条目:回到原文重读,改写或删除对应的笔记(以及受它影响的支柱、摘要、自测题)。改完不需要动 verdicts.json——校验通过文本指纹识别"已修改"。
- `bg check -w work --final` 通过后才能 build。
- 非 ok 的比例超过 15%:说明问题是系统性的。修完后 `bg audit --renew -w work` 重新抽样再查一轮。
- 核查结果(查了多少、通过多少、修正多少)会显示在导读页脚的可靠性说明里。
