# 逐章精读:怎么记笔记

读一章的目标不是"摘要",而是**还原这一章的论证**:作者在这里主张了什么、凭什么、用什么证明、承认了什么例外、反驳了谁。

## 顺序

1. `bg context cNN` —— 看全书假设、前面各章的主干、已有概念。
2. 通读本章(长章分批,读一批记一批)。**读完再下结论**:很多章的真正论点不在开头。
3. 先写 `role`:这一章在全书论证里起什么作用?(提出问题 / 建立概念 / 给出证据 / 反驳对手 / 给出方法 / 划定边界 / 背景铺垫……)写不出 role,说明还没读懂。
4. 找出主干(`core`),再补支撑它们的理由、证据、限定。
5. 用 `links` 把它们连起来。
6. 记下作者赋予专门含义的术语(`concepts`)。
7. `bg check cNN`,修到通过。

## 六种笔记类型(kind)

| kind | 是什么 | 判别问题 |
|---|---|---|
| `claim` 主张 | 作者断言为真的判断 | "作者认为……"说得通吗? |
| `reason` 理由 | 解释主张为什么成立的机制、原理、推理 | 它在回答"为什么"吗? |
| `evidence` 证据 | 研究、数据、案例、经历、引述——用来证明的材料 | 它是"发生过的事/查到的数",而不是道理吗? |
| `method` 方法 | 可以照着做的做法、步骤、准则 | 读者能据此行动吗? |
| `caveat` 限定 | **作者自己**承认的例外、前提、不适用的情形 | 作者在给自己的主张划边界吗? |
| `counter` 对手观点 | 作者引述、但**不同意**(或不完全同意)的他人观点 | 作者接下来会反驳或修正它吗? |

证据必须再用 `ev` 标明类型:`study` 对照研究/实验、`data` 统计数据、`case` 案例、`anecdote` 轶事/个人经历、`authority` 引用权威、`analogy` 类比、`reasoning` 推演/思想实验。如实标——一个朋友的故事是 `anecdote`,不是 `case`;没有对照组的调查是 `data`,不是 `study`。导读会据此统计每根支柱背后的证据构成,这是读者判断可信度的依据。

## 三个层次(weight)

- `core` 主干:删掉它,本章的论证就不成立。每章通常 1–5 条。
- `support` 支撑:主干的理由、关键证据、重要限定。
- `detail` 细节:次要例子、补充数字。导读默认折叠。

**检验**:只读本章的 core,能得到本章 role 所说的内容吗?能,就对了。

## 关系(links)

`{"from": A, "to": B, "type": T}` 读作"A T B":

| type | 读法 | 典型用法 |
|---|---|---|
| `supports` | A 支持 B | 理由/证据 → 主张 |
| `causes` | A 导致 B | 机制链条;两条方向相反的 causes 构成反馈回路 |
| `requires` | A 以 B 为前提 | 方法的某一步依赖前面的概念;后面的论断依赖前面的结论 |
| `refines` | A 细化/修订/举例说明 B | 子论点 → 总论点;后文修订前文 |
| `rebuts` | A 反驳 B | 作者的主张 → `counter` |
| `limits` | A 限定 B | `caveat` → 被限定的主张 |
| `applies` | A 落实 B | `method` → 它所依据的主张 |

方向按语义,与书中先后无关。端点可以是前面章节的命题 id。只连书里确实存在的关系;不要为了好看而连。

脚本会提示这些结构问题:证据没连到任何主张;`caveat` 没有 `limits`;`counter` 没有被 `rebuts`;非主干笔记完全悬空。

## 每条笔记怎么写

```json
{"id": "c03-k4", "kind": "evidence", "ev": "study", "weight": "support",
 "text": "在对 412 家企业的追踪中,采用季度复盘的企业三年后的存活率比对照组高出 37%。",
 "refs": ["c03-p021"], "quote": "四百一十二家企业"}
```

- `text`:**一个能独立读懂的完整句子**,只说一件事。脱离上下文也要知道在说什么——不要出现"这种做法""上述观点""他"这类需要回看才懂的指代。
- 证据类笔记要写出**关键事实**(谁、多少、什么结果),而不是"作者举了一个例子"。
- `refs`:最直接支撑这句话的 1–3 段。
- `quote`:从 refs 段落里**逐字复制**的片段,**通常 6–15 字就够**(上限 30),选有辨识度的(专名、数字、独特措辞),让读者在自己的书里一搜就到。不要改字,不要用省略号拼接。全书的 quote 合计不得超过原书的 5%,所以别摘整句。
- 数字照原文核对。原文写"百分之三十七",笔记写"37%"是可以的;脚本会对不上的数字给提示。

### 正反例

| ✗ 不好 | 为什么 | ✓ 改成 |
|---|---|---|
| "反馈的延迟问题" | 名词短语,没有判断 | "反馈延迟超过一个季度后,组织会把结果归因于最近的决策,而不是真正起作用的旧决策。" |
| "作者举了丰田的例子来说明这一点。" | 没有内容;"这一点"悬空 | "丰田在 1990 年代把质量反馈周期从月缩短到班次后,返工率下降了约四成。"(`evidence`/`case`) |
| "学习需要反馈,反馈需要及时,及时需要制度。" | 三件事挤在一条里 | 拆成三条,用 links 连接 |
| "很多管理者相信,绩效考核越频繁越好。"(标成 `claim`) | 这是作者要反驳的流行看法 | 标成 `counter`,再记一条作者的反驳并 `rebuts` 它 |
| 把原文句子稍改几个字 | 抄录 | 合上原文,用自己的话重新说 |

## 最常见的五个陷阱

1. **把对手的话记成作者的话。** 作者常用很长篇幅、很有说服力地陈述一个观点,然后才说"但是"。看到"人们常说""有一种流行的看法""X 教授认为""乍看之下",先别记——继续读到作者表态。作者"部分同意"时:同意的部分记成 `claim`,被修正的部分记成 `counter`,并写明作者保留意见在哪。作者**引述并赞同**的他人论点不是 `counter`:按内容记成 `claim`/`reason`/`evidence`(`ev: authority`),并在句子里点明出处和作者的态度("X 指出……,作者认同这一点")。
2. **只记开头和结尾。** 长章的关键论断常常埋在中段的案例之间。读完后问自己:中间三分之一我记了什么?(脚本会报告大段无锚点的范围。确实只是铺垫或重复,就在 `skipped` 里写明范围和原因——这是合法的,但必须是有意识的判断。)
3. **丢掉限定条件。** "在 X 条件下 A 导致 B"被记成"A 导致 B"。作者说"往往""在我们的样本里""除非……",都要保留;作者专门讨论的例外单独记成 `caveat`。
4. **概念漂移。** 同一个术语,作者在后面的章节可能重新定义。发现本章的用法和 context 里的定义不一致时,在本章 `concepts` 里再记一次,用 `note` 写明"本章修订了第 X 章的定义:……"。不要悄悄沿用旧定义,也不要给同一个概念换个名字。
5. **用自己的知识补书。** 你也许知道这个领域的真实研究,或者这本书的通行解读。不要写进笔记。笔记只反映**这本书这一版**说了什么;你的看法留到综合阶段的 `critique`。

## 概念(concepts)

只记作者**赋予了专门含义**的术语——自造的词,或被重新定义的日常用语。普通词汇不记。

```json
{"term": "迟滞窗口", "def": "从一个决策做出到它的后果可以被观测到之间的时间段。",
 "refs": ["c02-p008"], "aka": ["反馈窗口"], "note": "作者强调它不同于「响应时间」:后者是发现后果之后到采取行动的间隔。"}
```

## 序言、结语也是章

作者自己写的序言和结语同样要写笔记(检视阅读时读过一遍不算)。那里对全书论点的直接表述记成 `core`——综合阶段会把它们列入 `thesis_claims`,作为核心论点的出处。

## 明确跳过(skipped)

```json
"skipped": [{"from": "c05-p031", "to": "c05-p052", "why": "对前文实验的逐条流程描述,没有新论点"}]
```

## 写 JSON 的注意事项

- 字符串里出现英文双引号要写成 `\"`,或改用中文引号「」“”。
- 一章的笔记写完一次性落盘;长章可以先写前半批,读完后半批再补全同一个文件。
- 完整字段见 `schema.md`,完整样例见 `examples/mini/work/notes/`。
