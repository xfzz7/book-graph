# 第 0 步:全书定向(先看地图,再进城)

目的:读每一章之前,先对全书有一个**可被推翻的假设**。没有它,逐章抽取会变成孤立摘录;有它,每章才知道自己在回答什么。

## 做法

1. `bk skeleton -w work` —— 得到每章标题、规模、小节标题、开头与结尾各一段。
2. 如果书有序/导论/结语,再用 `bk read cXX` 读它们(这几处作者通常会直说全书要干什么)。**只读这些**,不要在这一步通读全书。
3. 写 `work/orient.json`。所有内容都是**假设**,后面读到与之不符的地方,要在章笔记里如实记录(caveat / revises),在综合阶段修正。

## 格式

```json
{
  "question": "这本书想回答的核心问题(一个问句)",
  "thesis_guess": "你对全书主张的最佳猜测(1~2 句,自己的话)",
  "genre": "argument | howto | narrative | science | memoir | reference | mixed",
  "audience": "作者心目中的读者 / 适合谁读",
  "parts_guess": [{"title": "第一部分", "chapters": ["c02", "c03"], "job": "这一部分在全书论证里承担什么"}],
  "risks": ["最容易读错/混淆的地方,例如:某个词作者另有定义;某个流行观点是被批评的对象;后面的章节可能修正前面的说法"],
  "watch": ["读各章时要特别留意的事:反复出现的术语、疑似的前后修正、需要对照的数据"]
}
```

## 判断体裁(决定后面的侧重)

| genre | 特征 | 侧重 |
|---|---|---|
| argument | 提出论点并论证 | 论证结构、前提、反驳 |
| howto | 教你怎么做 | method 卡 + 适用条件 + 失败情形 |
| narrative | 以故事/历史为骨架 | 故事背后的解释性论点;别把情节细节当论点 |
| science | 讲研究发现 | 证据类型、强度、研究局限 |
| memoir | 个人经历 | 作者从经历里得出的结论 vs 经历本身 |
| mixed | 多种混合 | 按章判断 |

## 完成标准
- `orient.json` 存在,`question` 是真正的问句,`risks` 至少 1 条。
- 没有抄原文:用自己的话写。
