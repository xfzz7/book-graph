# 第 5 步:独立核对(你是核对者,不是作者)

你拿到的是 `audit/batch_NN.md`。每个条目有:**待核对文本**,以及它所依据的**原文段落**(★ 是被引用的段落,其余是上下文)。

## 规则
1. **只依据原文段落判断**。不要用你自己对这本书/这个主题的背景知识——条目说得对不对,只看段落里写没写。
2. 条目里的“标注立场”(作者主张/他人观点/作者存疑)也要核对:段落里这话是**作者自己主张的**,还是作者转述别人的、批评的、假设的?
3. **要严。** 批次里混有少量被故意改坏的条目(改了数字、张冠李戴、说过头、引错段落)。你的任务就是把它们找出来。宁可多标一个“说过头”,也不要放过一个错误。
4. 不要看 `audit/_seeds.json`,不要修改 batch 文件。

## 逐条判断
对每个条目选一个 verdict:

| verdict | 含义 |
|---|---|
| ok | 忠实:每个事实/数字/限定都能在段落里找到,立场标对了 |
| overstated | 说过头:原文有保留(“大致”“经验法则”“可能”),条目说得更绝对;或加了原文没有的“所有/总是/必然” |
| distorted | 走样:数字、方向、因果、条件被改了 |
| unsupported | 原文找不到:这些内容不在给出的段落里 |
| misattributed | 归因错误:把他人观点/被批评的观点当成作者主张(或反过来) |
| too_vague | 太空泛:对照原文几乎没有信息量,换成任何书都成立 |

逐项检查清单:① 每个数字 ② 每个限定词 ③ 因果方向 ④ 谁在说 ⑤ 有没有多出原文没有的内容。

## 输出 `audit/verdicts_NN.json`(NN 与批次号一致)
```json
[
  {"id": "c04.k2", "verdict": "ok", "note": ""},
  {"id": "s03", "verdict": "distorted", "note": "原文是 78%→91%,条目写成 78%→98%", "fix": "(可选)建议的改法"}
]
```
**每个条目都要有一行**,包括 id 以 s 开头的。note 在 verdict 不是 ok 时必填,指出原文哪里不一致。
