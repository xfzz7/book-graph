# 章节笔记:格式与判断标准

一章写一个文件 `work/notes/<章id>.json`。它要回答三个问题:**这一章在回答什么?怎么回答的?凭什么?** 次要的是:它引入了哪些概念、和前后文怎么接上。

## 读的方法

1. 先看 `brief` 简报:前面章节说到哪了、哪些概念已经登记、前文留下了什么问题。
2. 按分块读原文(`[c3.p12]` 是段落锚点)。每读完一块,先记下这块里的命题和锚点,再读下一块。
3. 整章读完后再写 `question` / `answer` / `role`——它们是对整章的判断,不是对开头的印象。

## 格式

```json
{
  "chapter": "c3",
  "question": "这一章要回答的问题(一句问句)",
  "answer": "这一章的回答(一到两句,作者的结论)",
  "role": "mechanism",
  "claims": [
    {"id": "c3.1", "text": "完整的一句话,用你自己的话转述。", "kind": "claim",
     "voice": "author", "weight": 3, "anchors": ["c3.p4", "c3.p6-p7"]}
  ],
  "concepts": [
    {"term": "责任不对称", "definition": "作者意义下的定义,一两句。",
     "distinct_from": "容易混淆的东西,以及区别在哪(没有就省略)", "aliases": ["书中的其他叫法(可省略)"],
     "anchors": ["c3.p3"]}
  ],
  "links": [
    {"from": "c3.2", "to": "c3.1", "rel": "supports", "note": "可选:一句话说明"}
  ],
  "threads": {
    "opens": ["本章提出、但留待后文回答的问题(写成一句问句)"],
    "closes": ["c1#2: 本章怎样回应了简报里编号为 c1#2 的线索"]
  }
}
```

### 字段取值

`role`(本章在全书论证里的作用,选最主要的一个):
`opening` 开篇立问题 · `problem` 描述问题/现象 · `concept` 立概念 · `mechanism` 解释原因/机制 · `evidence` 主要在摆证据 · `objection` 处理反方意见 · `solution` 给方案 · `application` 讲具体应用 · `synthesis` 收束全书 · `limits` 谈局限 · `background` 铺背景

`kind`(命题类型):

| kind | 含义 | 例 |
|---|---|---|
| `claim` | 判断、主张、结论 | 流程大多是信任流失后的替代品 |
| `mechanism` | 解释为什么/怎样发生 | 撤流程的风险集中在个人,留流程的成本分散,所以没人撤 |
| `method` | 可以照做的做法 | 撤流程前先约定可容忍的差错范围 |
| `evidence` | 案例、数据、实验、经历(写出关键数字和结果) | 46 家企业调查:流动率 >20% 的部门审批步骤是 <10% 的 2.3 倍 |
| `definition` | 作者对概念的界定 | —— |
| `concession` | 作者承认的限制、让步 | 该调查只是相关性的 |
| `objection` | 作者讨论并反对/质疑的观点或做法(配 `voice: reported`) | 有人主张用自动化替代人工审批 |

**他人观点只写他人的观点**:`voice: reported` 的命题文字里不要夹带作者的回应。原文是"有人说 X;我认为 Y"时,拆成两条:X(reported)和 Y(author),再写 `Y rebuts X`。

没有单独的"限定"类:作者给**自己的**结论加的条件、范围、保留,用 `concession`;命题之间的限定关系用 `rel: qualifies`。作者批评的流行做法(如"搞一场精简运动"),用 `objection` + `reported`,再用 `rebuts` 连到作者的回应。

`voice`:`author`(作者自己的立场,默认)或 `reported`(作者转述的他人观点、流行看法、他要反驳的说法)。**作者反对的观点一定是 `reported`**,并用一条 `rebuts` 关系连到作者的回应。

`weight`:`3` 本章核心(通常 1–3 条,`answer` 应该由它们构成)· `2` 重要支撑 · `1` 细节。导读的逐章部分只展示 weight ≥2 的命题,weight 1 的只在展开时出现。

`rel`(读作 `from <rel> to`,方向按语义,与书中先后无关):
`supports` 支持/佐证 · `explains` 解释(机制解释现象)· `causes` 导致 · `rebuts` 反驳 · `qualifies` 限定/补充条件 · `applies` 应用于 · `answers` 回答/化解(方案→问题)· `requires` 以…为前提

章内关系写在本章;跨章关系留到全书综合时写进 `cross_links`(那时你能看到全书)。

**读者看得到的文字里不要写内部编号**:`question`/`answer`/`text`/`threads` 里提到别的章时写章名("第二章"、"序言"),不要写 `c3`。(渲染器会兜底替换,但写章名更自然。)`threads.closes` 开头的 `c1#2:` 是线索编号,会被渲染成那条线索的原话;只回应了一部分时写 `c1#2(部分): …`,这条线索会继续出现在后面章节的简报里。

## 好命题的标准

- **能独立读懂**:不看上下文也知道在说什么。✗「作者对此持保留态度」→ ✓「作者认为在修复信任之前做审批自动化,会把代偿流程固化进系统」。
- **一条只说一件事**,但要说完整:主张写出"是什么",机制写出"为什么",证据写出"谁、做了什么、结果数字"。
- **保留关键数字和专有名词**:读者事后最想查的就是这些。数字要和原文一致。
- **转述**:换句式、换说法,不要连续抄 20 字以上。书中术语原样保留。
- **只写书里有的**。你的评价、联想、外部知识,一概不写进章节笔记。
- **数量由内容决定**:经验上每千字 1–3 条;很短的书(几千字)可以略密,但每千字超过 4 条 check 会提示。宁可少而准,不要把每段都改写一遍——那是复述,不是导读。导读总篇幅超过原书的 30%(长书)或 100%(短书)时 check 会提示。

## 概念

只登记**作者赋予特定含义的词**(他自造的词,或他用法与日常不同的词),不要把普通名词都当概念。`definition` 写作者的意思;`distinct_from` 写读者最可能把它和什么混淆(包括日常含义),这是帮助"读懂"最有价值的一句。简报里已登记的概念再次出现时,沿用同一 `term`;若作者在本章深化了定义,写一条新的 `definition` 命题即可。

## 自查清单(写完、跑 check 前)

- [ ] `answer` 能被 weight=3 的命题支撑
- [ ] 作者转述后反驳的观点都标了 `reported`,并有 `rebuts` 关系
- [ ] 每个分块都有命题引用(check 会提示)
- [ ] 证据类命题写出了数字和结果
- [ ] 简报里的"前文线索"本章若有回应,写进了 `threads.closes`
