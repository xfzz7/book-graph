# 事实核查

`bg verify-sheet work` 生成 `work/verify/sheet.md`,包含两类条目:
- 命题(id 如 `c3.2`):骨架命题、全部"他人观点"、贴合度最低的 5 条、随机 10 条,附引用的原文段落;
- 综合层陈述(id 如 `S:K2`、`S:answer`、`S:mis1`、`S:quiz3`、`S:admit1`):关键思想、全书回答、误读纠正、自测答案、作者自承局限,附它们所依据的命题和原文段落。这些是读者最先读到的话,夸大和走样最常出在这里。

**最好由一个没有参与写作的子代理来做**:只给它 `sheet.md` 和本文件,不给它章节笔记和综合。自己核自己,容易用记忆替原文作证。

## 判定

对每一条,**只看给出的原文段落**,判断:

| verdict | 条件 |
|---|---|
| `ok` | 段落明确表达了这层意思;数字、主体、方向都对;`voice` 正确 |
| `partial` | 大体对,但有夸大、遗漏关键限定、数字不准,或锚点只覆盖了一半(另一半在别处) |
| `wrong` | 与原文矛盾:方向反了、主体错了、把作者反对的观点当成作者的、数字错 |
| `unsupported` | 给出的段落里找不到这层意思(可能锚点引错了,也可能是编的) |

特别留意:
- **立场归属**:`voice: author` 的命题,作者真的赞成吗?还是他转述后反驳的?
- **程度词**:"总是/大多/有时","证明/表明/提示"——不要把相关说成因果、把"可能"说成"一定"。
- **数字**:逐个对照。
- **类型标签**:标成 `evidence` 的,原文真是案例/数据吗?作者设想的情境、举的假设例子不算证据。
- 综合层陈述:是否比所依据的命题说得更满?自测答案是否被原文支撑?

## 输出

`work/verify/verdicts.json`:

```json
[
  {"id": "c3.2", "verdict": "ok"},
  {"id": "c4.5", "verdict": "partial", "reason": "原文说的是'大多',命题写成了'总是'", "fix": "改为'大多数'"}
]
```

非 `ok` 的条目必须有 `reason` 和建议的 `fix`。随后由主流程修改(命题的文字、锚点、kind、voice 任一改动都算;综合层陈述须改文字),或删除;校验器会检查这些条目确实被改过。改完不需要重新生成核查单。
