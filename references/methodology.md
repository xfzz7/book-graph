# 标注方法

## 命题(节点)

1. 一个节点 = 一个**完整句子**,能独立读懂,有主张或有信息量;不是名词短语。
2. **转述**,不要照抄原文;一条命题只说一件事。
3. 类型:
   - `V` 观点:作者主张/判断
   - `M` 机制:解释“为什么会这样”的因果或原理
   - `F` 方法:可以照着做的做法
   - `E` 依据:案例、实验、数据、亲身经历
4. 短标签 `h` ≤ 10 字,用于图上显示;细节全放在句子里。
5. `basis=e` 书中明确写出;`x` 属于作者经历/外部案例。

## 关系(边)

方向规则:**从先说的指向后说的**,表达“前者如何作用于后者”。

| 类型 | 读法 | 例 |
|---|---|---|
| cause | A 导致 B | 路径依赖 → 退行螺旋 |
| support | A 支持/论证 B | 实验 → 观点 |
| solve | A 化解 B | 方法 → 问题 |
| require | A 需要 B(前提) | 行动 → 条件 |
| oppose | A 与 B 对立 | 成长型 ↔ 固化型 |
| refine | A 细化/展开 B | 子概念 → 总概念 |

- `basis=e`:书里明确说了;`basis=i`:你推断出来的(页面画虚线,**务必如实标**)。
- 反馈回路(如“拖延⇄内耗”)书里常常只写单向,另一向用 `i` 补上,才能让回路出现。
- 每条边写 `note`,一句话说明依据,方便人工复核。

## 大纲

篇 → 章 → 要点;要点是作者顺序里的“一句话主题”,并挂接对应命题 id。大纲回答“书怎么讲”,关系网回答“书里各说法怎么互相作用”,两者不要互相复制。

## 质量自检

- 观点类命题有没有被 support/refine 佐证?(`analyze` 会列出缺佐证的)
- 推断边占比是否过高(超过 ~30% 要警惕)?
- 社群是否与章节完全重合?完全重合说明关系只是章内串联,没发现跨章结构。
