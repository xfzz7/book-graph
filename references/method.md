# 设计原理(维护者读)

## 为什么不再是"命题图谱"
v0.1 把一本书拆成句子级命题 + 有向类型边,再用力导向图展示。问题:
1. 形式先行:读者要的是"读懂",不是"一张图"。100+ 节点的力导向图是毛线团,标签只显示 ≤10 字,读者看不到论证。
2. 没有重点:所有命题平权,没有"承重"概念,总览与细节混在一起。
3. 没有可核对性:命题只记章号,"禁止抄录"导致读者无法回到原文验证,LLM 的编造与曲解无从发现。
4. 缺少理解所需的层次:没有全书主张/支柱、没有概念表、没有证据强弱与局限、没有作者的自我修正、没有自测。
5. 没有上下文管理:逐章独立抽取、一次性连边,没有滚动记忆;没有进度状态,中断即丢。

## 理解一本非虚构书,需要什么
1. 要点:它回答什么问题、答案是什么(先建立地图——先行组织者)。
2. 结构:论证怎么搭——支柱、理由、证据、反驳;每章承担什么任务。
3. 概念:作者的术语与区分(误解的第一来源)。
4. 证据与强度:该信多少。
5. 自我修正与限定:后文改了前文;经验法则不是定律。
6. 立场:谁在说——作者的主张还是被批评的流行看法。
7. 提取练习:自测(检索练习比重读更有效)。

对应数据结构:卡片(tier/kind/voice/parent+rel/ev)→ 论证树;concepts;critique;misreadings;questions。

## 为什么是"树 + 少量跨章修正"而不是图
论证本质上是树:结论←理由←证据,加上少数反驳与修正。因果回路是少数、可显式命名的结构(chains)。强行建全连通图会产生"为了连通而连"的边,且无法阅读。

## 可靠性机制(防编造/曲解/照抄)
| 机制 | 防什么 | 位置 |
|---|---|---|
| refs + 逐字 anchor | 编造;让读者能回原文 | check.py |
| 数字必须出现在引用段落 | 编造数字(最致命) | check.py |
| 2-gram/词干重合率 | 引错段落、说多了 | check.py(仅同语种) |
| 连续相同字符检测 | 照抄(版权) | text.CopyIndex |
| voice 三态 | 把被批评的观点归给作者 | schema |
| ev.limit、critique 的 book/outside 分离 | 夸大证据;外部知识冒充书中内容 | schema/check |
| 独立核对 + 种子故障 | 作者看不出自己的错;核对者不认真 | audit.py |
| 覆盖/位置偏倚报告 | 漏读、前重后轻 | check.py |
| 文本哈希 | 核对后又改动 | audit.py |

## 上下文管理
- 状态全在文件;`bk status` 恢复现场。
- 章前简报 = 滚动记忆(全书定向、前面各章一句话+关键卡、已有术语、下一个 id),大小受控。
- 章分块(默认 ≈7000 tokens);块边界落在小节处,不切段。
- 章与章只通过 brief 与最终 digest 交流,所以可并行。
- 综合阶段读 digest(压缩的卡片清单)而不是原文。

## 已知取舍
- anchor 是极短的原文片段(合理引用量级),换来可核对性。
- 词重合检查对跨语种无效;靠 anchor/数字/独立核对兜底。
- tier 与 pillars 是 LLM 判断,脚本只能查分布,不能查对错。
